# Five-project pilot

This is a later validation milestone using five real, existing browser-agent projects.
It is not a request to build five new applications. Repository fixtures prove technical
behavior; they do not establish customer demand.

All approved features remain committed. Pilot findings may change defaults, sequencing
or interaction design. Any proposed scope change needs an explicit decision.

## Recruitment and baseline

For each consenting maintainer, record a repository/path, integration version,
representative complete workflow, existing permission/review/logging code, required
protections and agreed legitimate outcomes. Choose distinct existing projects rather
than variants of the demo. Never collect real credentials or raw payment information.

Run the agreed safe test workflow before and after integrating Acira. Use test accounts
and representative non-sensitive data. Measure:

| Field | Measurement |
| --- | --- |
| Setup | Minutes from an already-working browser environment to first correct guarded run |
| Integration cost | Files/lines changed and manual steps |
| Replaced maintenance | Concrete prompts, permission rules, logging or review code removed |
| Completion | Agreed legitimate scenarios completed / attempted |
| Burden | Reviews per complete task; duplicates; avoidable reviews; false blocks |
| Comprehension | Can the reviewer identify target, account, recipient and values? |
| Continued use | Voluntary repeat use over two weeks; support needed; concrete benefit |

## Complete journey

Initialize → import one useful policy → run the existing agent → open the dashboard
later → resolve review → inspect the recorded outcome. Include two folders using one
dashboard and a Saved → Active update. Exercise file-only mode and dashboard outages.

For approval burden, compare individual field reviews, bounded form operation, routine
grant and fresh critical submission. Record whether grouping removes duplicate work
without widening authorization.

Initial learning targets:
- Setup within five minutes once the environment works.
- All agreed legitimate scenarios finish without weakening required protections.
- No duplicate review of the same operation.
- Three of five maintainers voluntarily use Acira repeatedly over two weeks and identify
  a maintenance benefit.

These are learning criteria, not statistical proof. An empty results file means no
evidence, not a failed or successful pilot. Results must come from actual use.
